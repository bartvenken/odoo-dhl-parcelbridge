ParcelBridge for DHL eCommerce Benelux

Create real shipments from Odoo - labels and trackers on delivery validation.

Backend-first carrier integration for DHL eCommerce Benelux (BE / NL / LU).

What it does

📦

Real shipments

Validating a delivery triggers a POST to api-gw.dhlparcel.nl/shipments. Label PDF and tracker come back and are attached to the picking automatically.
🕵

Sandbox / production detection

Every save decodes the JWT and reads the sandbox claim. A red banner appears if a test key ends up in a production carrier - no accidental fake shipments.
🛠

Support-friendly

One-click debug bundle exports the full DHL context for any delivery (config, recipient, payload, last error) with credentials redacted - send it to support and be done.

Key features

  • Native delivery.carrier provider (delivery_type = 'dhlparcel') - behaves like any other Odoo carrier: works with sales orders, Add Shipping wizard, checkout, backorders.
  • All DHL Parcel product types supported: Envelope, Mailbox parcel, Parcel up to 10 / 20 / 31 kg, Pallet up to 1000 kg, plus Mixed and Operator picks at packing for multi-type or open-choice flows.
  • Multicollo via a "Number of parcels" field on the delivery, or via native Odoo Put in Pack for accurate per-box weights.
  • Recipient-aware filtering: consumer-only carriers (Envelope, Mailbox) auto-hidden for business customers, and vice versa - on both backend Add Shipping and webshop checkout.
  • Test Connection button + persistent "Last Test Result" section on the carrier - no more digging through server logs to check if credentials are alive.
  • Verify Contract button: probes DHL's /products endpoint for each enabled destination country and recipient type, and reports which routes are covered by your DHL contract. Missing products (e.g. no CON2C activated for UK consumer) are flagged before they cause a rejected shipment.
  • Debug logging hooked on Odoo's native Debug requests toggle. Every API call written to Settings > Technical > Logging, with credentials redacted.
  • Access control: API credentials restricted to a dedicated DHL Parcel Administrator group. Regular shipping-managers can use carriers without seeing keys.
  • 4 languages included: English, Dutch, French, German.
  • Every DHL error surfaced in a persistent field on the carrier + in Odoo's log - no silent failures.
  • OPL-1 license, source-readable, redistribution not allowed.

How it works

1
 Install the module. A new provider "ParcelBridge for DHL eCommerce Benelux" is added to the shipping-method form.
2
 Create one shipping method per DHL parcel type you offer, and enter your DHL User ID + API Key + Account ID.
3
 Click Test Connection to confirm the credentials, then Verify Contract to check that your DHL account has the right products active for the destinations you enabled. Both write a persistent report on the carrier form.
4
 On any sale order, click Add Shipping and pick your DHL method. Confirm.
5
 Validate the delivery. The module POSTs to DHL, receives a multi-page label PDF and one tracker per piece, attaches the PDF, stores the trackers. Done.

Requirements

  • Odoo 17 (community or enterprise). Separate builds available for 18 and 19.
  • A DHL eCommerce Benelux account with API access activated on the contract (ask your DHL contact if unsure - API access is not the default, and it needs to be enabled by DHL before you can create keys in the DHL portal).
  • Ships from Belgium, the Netherlands or Luxembourg. Delivers to any of the 31 destinations supported by DHL Parcel.
